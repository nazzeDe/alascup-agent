# 部署文档

生产环境（LoongArch 宿主机）部署指南。开发机交叉构建见 `doc/开发环境.md`。

所有构建、启动、测试命令统一通过 `make` 执行（见项目根目录 `Makefile`）。

## 配置

### 环境变量

在项目根目录创建 `.env` 文件（可选），用于覆盖默认运行时参数：

```bash
LOG_LEVEL=INFO
```

### 配置文件准备

系统运行前需要准备配置目录 `web-server/config/`，放置以下文件：

- `servers.json`：MCP Server 连接配置

```json
{
  "servers": [
    {
      "name": "tool-server",
      "url": "http://tool-server:8001",
      "transport": "streamable-http"
    },
    {
      "name": "rag-server",
      "url": "http://rag-server:8002",
      "transport": "streamable-http"
    }
  ]
}
```
- `prompt/`：System prompt section 文件，一个 `.md` 对应一个 section（`identity.md`、`rules.md`、`tool_usage.md`）。不存在的文件使用内置默认值
- `rules.json`：工具调用安全规则
- `llm.json`：LLM 接入配置（API Key、API URL、模型标识）

示例目录结构：
```
./web-server/config/
  servers.json
  prompt/
    identity.md
    rules.md
    tool_usage.md
  rules.json
  llm.json
```

### 安全规则配置

`rules.json` 管理工具调用策略，包含两个列表：
- `whitelist`：覆盖默认危险等级，列入的工具自动审批通过
- `blacklist`：禁止使用，列入的工具不可调用

规则引擎只做**工具名级别**的匹配，不做参数级判定。参数级风险由 tool-server 的 `classify_tool` 动态判定负责。

规则判定顺序：
1. 命中 `blacklist` → 拒绝执行，记录审计。
2. 命中 `whitelist` → 跳过审批直接执行，记录审计。
3. 未命中 → 按默认策略：只读放行，高风险进入审批。

示例：
```json
{
  "whitelist": [
    {
      "tool_name": "delete_temp_files",
      "description": "原本需用户确认，加入白名单后自动审批通过"
    }
  ],
  "blacklist": [
    {
      "tool_name": "reboot_system",
      "description": "高危工具，禁止使用"
    }
  ]
}
```

## 服务通信

所有服务使用 `network_mode: bridge`，通过 Docker Compose 内部 DNS 互相访问：

| 通信路径 | 地址 | 说明 |
|----------|------|------|
| frontend → web-server | `http://web-server:8000` | Nginx 反向代理 `/api/*` |
| web-server → tool-server | `http://tool-server:8001` | MCP JSON-RPC |
| web-server → rag-server | `http://rag-server:8002` | MCP JSON-RPC |

`tool-server` 和 `rag-server` 端口仅限容器内部通信，不对宿主机暴露。

## 验证与访问

### 服务端口

| 服务 | 端口 | 对外暴露 | 说明 |
|-----|------|---------|------|
| frontend (Nginx) | 80 | 是 | 前端应用入口 |
| web-server (FastAPI) | 8000 | 是 | 后端 API，SSE 流式响应 |
| tool-server | 8001 | 否 | MCP 协议，仅容器内部 |
| rag-server | 8002 | 否 | MCP 协议，仅容器内部 |

### 健康检查
```bash
# 前端
curl http://localhost/

# 后端 API
curl http://localhost:8000/api/health
```

## 日志持久化

应用日志挂载到宿主机 `./logs/`：

```yaml
volumes:
  - ./logs/web-server:/app/logs:Z
  - ./logs/tool-server:/app/logs:Z
  - ./logs/rag-server:/app/logs:Z
```

审计日志写入 PostgreSQL，不依赖文件持久化。

## LLM 配置

LLM 接入信息通过 `web-server/config/llm.json` 配置，格式如下：

```json
{
  "api_key": "your-api-key",
  "api_url": "https://api.openai.com/v1",
  "model": "deepseek-v4-pro",
  "summary_model": "deepseek-v4-flash"
}
```

- `api_key`：模型服务密钥
- `api_url`：模型服务地址（OpenAI 兼容 API）
- `model`：默认诊断模型标识
- `summary_model`：Context Manager 摘要压缩用的轻量模型（可选，不配置则复用 `model`）

web-server 启动时读取该文件。前端请求可携带 `model` 字段覆盖默认模型。
