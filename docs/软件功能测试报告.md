## 5. 重点测试记录

### 5.1 输入安全检查

测试覆盖四类规则：

1. 忽略、覆盖或改写系统安全指令。
2. 索取 system prompt 或开发者消息。
3. 索取密码、API Key、访问令牌或私钥。
4. 绕过审批、确认、权限或安全检查。

关键断言：

- 命中后先返回 `session_init`，随后返回 `PROMPT_INJECTION_BLOCKED` 和 `done`。
- 被拒绝消息不会进入 LLM 输入。
- `INPUT_REJECTED` 审计事件包含 `rule_id` 和原因。
- 无效正则配置和评估异常按 `BLOCK` 处理。
- “不要泄露 system prompt”“审批后再重启”等正常安全表达允许通过。

下面是 fail-closed 测试的实际断言。无效规则不会退化成“跳过安全检查”，而是返回可审计的固定拒绝结果。

源码：`web-server/tests/unit/test_security.py`

```python
gate = InputSafetyGate(
    [
        InputSafetyRule(
            id="invalid_rule",
            patterns=["("],
            reason="invalid test rule",
        )
    ]
)

assessment = gate.assess("Check CPU usage.")
assert (
    assessment.decision,
    assessment.rule_id,
    assessment.reason,
) == (
    "BLOCK",
    "input_safety_evaluation_error",
    "Input safety policy evaluation failed",
)
```

结果：全部通过。

### 5.2 工具风险分级与受控执行

测试覆盖：

- blacklist 优先拒绝。
- whitelist 和只读工具自动批准。
- 非只读工具进入审批。
- Bash AST 解析失败时不能免审批。
- 敏感路径、重定向、命令替换、网络请求、shell wrapper 和可写 flag 被识别。
- tool-server 校验 `approval_status`、`request_id`、`chat_id` 和共享鉴权。
- 直接调用可变工具不能绕过 `execute_tool`。

MCP 集成测试直接验证了 Bash 动态分类和防绕过路径。相同的 `bash` 工具根据本次命令返回不同结果：`ls /tmp` 可作为只读诊断，`rm -rf /tmp` 不能免审批；直接调用可变工具则返回安全违规。

源码：`tool-server/tests/test_mcp_integration.py`

```python
safe = await mcp_client.call_tool("bash_classify", {"command": "ls /tmp"})
unsafe = await mcp_client.call_tool(
    "bash_classify", {"command": "rm -rf /tmp"}
)

assert safe.structured_content == {"safe": True}
assert unsafe.structured_content == {"safe": False}

result = await mcp_client.call_tool(
    "bash", {"command": "echo bypass", "timeout": 2}
)
assert result.structured_content["error"]["data"] == (
    "mutable tools must be called through execute_tool"
)
```

结果：全部通过。

### 5.4 SSE 与会话恢复

测试覆盖：

- `session_init` 是首事件，`done` 是末事件。
- reasoning、assistant、tool call、tool result 和审批事件在同一 SSE 流中传输。
- 工具调用与结果通过稳定 `call_id` 配对。
- 断连、异常和拒绝路径仍能关闭前端状态。
- 历史会话恢复字符串、对象、数组、数值、布尔值和 `null` 工具结果。
- 工具结果信封中的错误和执行耗时可以恢复。

历史结果测试不是只覆盖字符串。参数化用例把六种 JSON 值写入持久化结果信封，再确认 API 适配后的 `output` 完全一致。

源码：`frontend/vue-project/src/__tests__/session-api.test.ts`

```typescript
it.each([

  ['number', 42],
  ['boolean', true],
```

## 7. 测试方法说明

本轮新增的输入安全门、历史证据适配、工具证据卡和 RCA 契约均以行为测试保护。测试关注可观察结果，例如“是否在 LLM 前拒绝”“刷新后结果是否一致”“普通对话是否避免长模板”，不为简单 getter 或框架默认行为堆叠无价值用例。

每项修改完成后执行重构，生产代码与测试代码分别保持明确职责。测试覆盖率作为风险提示，不作为单独的质量结论。

## 8. 已知边界

- Prompt Injection 测试证明已知规则有效，不代表覆盖所有语义改写、编码混淆和未知攻击。
- 当前正则规则没有独立执行超时。
- RCA 通过了 prompt 契约测试，真实模型准确率尚未量化。
- 本次 E2E 使用 Mock API，未覆盖真实 LLM、PostgreSQL、MCP 网络和 eBPF 全链路。
- LoongArch/麒麟 V11 Live E2E 和实机截图需要按远程 runbook 单独执行。
- 多用户并发、长时间稳定性和故障注入属于后续专项测试。

## 9. 测试结论

当前版本 813 个自动化用例全部通过，核心功能闭环已有单元、集成、前端组件和浏览器 E2E 四层证据。输入安全、工具审查、审批、受控执行和历史回看均有直接行为测试，满足初赛演示和文档提交所需的功能验证基础。

正式答辩前还应补两类现场证据：真实模型的代表性 RCA 样本，以及 LoongArch/麒麟 V11 环境中的健康检查、工具发现和关键流程截图。
