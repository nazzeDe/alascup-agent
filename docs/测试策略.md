# 测试策略

本文说明 Alascup Agent 的测试目标、分层、执行命令和质量标准。测试目标不是追求覆盖率数字，而是保护关键行为：安全审批、MCP 工具调用、Agent 流程、SSE 前端交互和服务部署可用性。

## 测试目标

测试优先覆盖风险最高、最影响比赛演示的路径：

- 用户发送消息后，系统能创建会话并稳定返回 SSE 流。
- 只读工具能自动执行，高风险工具必须经过审批。
- 未审批或非法 `request_id` 的工具调用必须被拒绝。
- MCP 工具注册、伴生分类工具、`execute_tool` 执行链路必须可验证。
- 前端能正确展示消息、工具调用、审批块、错误提示和会话列表。
- Docker 测试栈能启动，Live E2E 能连通真实 web-server、tool-server 和 PostgreSQL。

## 测试分层

| 分层 | 目标 | 主要工具 | 运行环境 |
|------|------|----------|----------|
| 单元测试 | 验证单模块业务规则、状态转换和错误处理 | pytest、Vitest | 本地进程，依赖 mock |
| 集成测试 | 验证服务内协作和 MCP client/server 协议链路 | pytest、FastMCP Client | 本地进程，临时目录 |
| Mock E2E | 验证前端完整交互，不依赖后端稳定性 | Playwright route mock | Vite dev server |
| Live E2E | 验证真实服务栈可用性 | Playwright、Docker Compose | nginx + web-server + tool-server + PostgreSQL |

## 目录结构

```text
web-server/tests/
  unit/              # web-server 单元测试
  integration/       # web-server API、DB、SSE 集成测试

tool-server/tests/
  test_*.py          # tool-server 单元测试
  test_mcp_integration.py  # FastMCP client/server 集成测试

frontend/vue-project/src/__tests__/
  *.test.ts          # Vitest 单元测试

frontend/vue-project/tests/e2e/
  *.spec.ts          # 前端 Mock E2E

frontend/vue-project/tests/e2e-live/
  *.spec.ts          # 真实测试栈 Live E2E
```

## 执行命令

推荐从仓库根目录执行：

| 命令 | 作用 |
|------|------|
| `make test-unit` | 运行 web-server、tool-server、frontend 单元测试 |
| `make test-integration` | 运行 web-server 和 tool-server 集成测试 |
| `make test-e2e` | 运行前端 Mock E2E，不需要后端 |
| `make test` | 运行单元、集成、Mock E2E |
| `make test-coverage` | 生成 Python branch coverage 和前端 coverage 报告 |
| `make up-test` | 启动 Live E2E 所需 Docker 测试栈 |
| `make down-test` | 停止 Docker 测试栈 |

前端也可以单独执行：

```bash
cd frontend/vue-project
bun run test
bun run type-check
bun run test:e2e
E2E_BASE_URL=http://localhost bun run test:e2e:live
```

## Marker 规则

Python 服务使用 `unit` 和 `integration` marker。`web-server/tests/conftest.py` 会按目录自动补 marker，避免测试文件漏标后被 Makefile 跳过。

`tool-server` 的单元测试默认使用 `pytestmark = pytest.mark.unit`。MCP 集成测试使用 `pytestmark = [pytest.mark.integration, pytest.mark.asyncio]`。

## 覆盖率口径

覆盖率用于发现盲区，不作为盲目补测试的目标。

`make test-coverage` 当前执行：

```bash
cd web-server && uv run pytest tests/ --cov=src --cov-branch --cov-report=term-missing
cd tool-server && uv run pytest tests/ --cov=src --cov-branch --cov-report=term-missing
cd frontend/vue-project && bun run test -- --coverage
```

前端 coverage 已排除 Playwright 配置、E2E、类型定义、端口接口和入口文件，避免报告被非业务代码干扰。

## 质量优先级

| 优先级 | 范围 | 标准 |
|--------|------|------|
| P0 | 安全审批、MCP 协议、`execute_tool`、伴生分类工具 | 必须有明确断言，失败时能阻止危险行为 |
| P1 | Agent 循环、SSE、错误恢复、会话生命周期 | 覆盖核心状态变化和用户可见结果 |
| P2 | 前端 UI、可观测性、配置加载 | 覆盖关键交互和容易回归的分支 |

P0/P1 测试优先写“能抓住真实 bug”的断言，例如审批状态、错误码、SSE 事件顺序、工具执行状态，而不是只检查函数被调用。

## 完成标准

一次可交付测试基线应满足：

- `make test-unit` 通过。
- `make test-integration` 通过。
- `make test-e2e` 通过。
- `make test-coverage` 可运行并生成有效报告。
- 比赛演示前执行 `make up-test` 后，`E2E_BASE_URL=http://localhost bun run test:e2e:live` 通过。
- 测试失败信息能定位到具体行为，而不是只暴露超时或选择器失效。

## Live E2E 环境说明

`docker-compose.test.yml` 启动完整测试栈：

- frontend: nginx 暴露 `http://localhost`
- web-server: 暴露 `http://localhost:11450`
- tool-server: 暴露 `http://localhost:11451`
- postgres: 仅暴露在 Docker 网络内，避免占用宿主机 `5432`

web-server 在测试栈中使用只读文件系统，并通过 tmpfs 提供 `/tmp` 和 `/app/logs`，保证部署约束更接近生产环境。
