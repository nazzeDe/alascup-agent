# 测试策略

全局约束，所有子项目必须遵守。

## 测试分层

| 分层 | 范围 | 占比目标 |
|------|------|----------|
| 单元测试 | 单个模块内部逻辑（函数、类、模型） | ~60% |
| 集成测试 | 服务内模块协作 + 服务间 MCP 通信 | ~30% |
| E2E 测试 | 完整用户路径 | ~10% |

## TDD 规范

```
1. 写测试用例，测试失败（Red）
2. 写最小实现，测试通过（Green）
3. 重构，保持测试通过（Refactor）
```

每个公开函数/方法都应有对应测试覆盖；对于纯数据映射、薄包装和稳定的简单委托函数，可以按同类行为合并测试，但不能跳过关键分支。先写测试文件再写实现文件。

## 环境分层

| 环境 | LLM | MCP Server | 宿主机 |
|------|-----|-----------|--------|
| 单元 | Mock | 不涉及 | 不涉及 |
| 集成 | Mock | fastmcp test server | 临时目录 |
| E2E | Mock（预定义序列） | Docker 容器 | test 挂载 |

**所有测试不使用真实 LLM**，保证可重复。

## 测试目录结构

```
web-server/tests/     # web-server 测试用例与数据
tool-server/tests/    # tool-server 测试用例与数据
```

E2E 测试使用 docker-compose.test.yml 启动完整服务栈。测试用例规格见 `doc/e2e测试.md`。

各子项目的测试用例规格、测试数据、mock 配置见各自 `tests/README.md`。

### 测试分类

Python 服务使用 **pytest markers** 区分测试类型：

```python
@pytest.mark.unit
def test_rule_engine():
    ...

@pytest.mark.integration
def test_mcp_communication():
    ...
```

各服务 `tests/conftest.py` 中注册 `unit` 和 `integration` marker。

## 覆盖率工具

| 语言 | 工具 |
|------|------|
| Python (web/tool) | pytest-cov |
| 前端 (JavaScript) | vitest (内置) |

覆盖率底线见下方优先级表。

## 优先级

| 优先级 | 范围 | 覆盖率底线 |
|--------|------|----------|
| P0 | 审查层、MCP 协议（classify_tool / execute_tool）、OpenAPI 契约 | ≥ 90% |
| P1 | Agent 循环、错误恢复链、只读预执行（AG-007）、MCP 通信 | ≥ 80% |
| P2 | 前端 UI、可观测性（剖析器/调试日志/错误日志）| 全部通过 |

## 测试选型原则

- P0 路径必须精确覆盖到分支和状态变化
- P1 路径优先覆盖端到端行为，不强求每个内部 helper 独立成测
- P2 以可用性和回归防护为主，允许围绕关键场景做聚合测试
- 真实外部依赖优先用 mock 或 test server 替代，只有协议兼容性验证才考虑受控集成环境

## 完成标准

- 所有 P0 测试通过且覆盖率 ≥ 90%
- 所有 P1 测试通过且覆盖率 ≥ 80%
- 所有 P2 测试通过
- E2E 核心场景（只读诊断、高风险审批、审批拒绝）通过
- 可观测性模块（剖析器/调试日志/错误日志）有专项测试覆盖
