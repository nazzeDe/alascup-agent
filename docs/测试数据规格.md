# 测试数据规格

各层测试所需的 Mock 数据集中索引。具体内容见各服务 `tests/README.md`。

## web-server Mock 数据

**LLM 响应序列**（见 `web-server/tests/README.md` Mock 配置章节）：
- 只读诊断序列（感知 → tool_call → 分析）
- 高风险含审批序列（计划 → 确认 → 执行）
- 审批拒绝序列
- 执行失败序列

**rules.json**（见 `web-server/tests/README.md` 测试 rules.json）：
- whitelist: delete_temp_files
- blacklist: reboot_system

**依赖注入**（见 `web-server/README.md` 依赖注入章节）：
- `llm_adapter`: MockLLMAdapter（预定义响应序列）
- `session_manager`: InMemorySessionManager（测试不依赖数据库）
- `audit_logger`: InMemoryAuditLogger
- `tracer`: NullTracer
- 审批超时：测试通过 mock 或依赖注入缩短等待

## tool-server Mock 数据

**模拟宿主机文件**（见 `tool-server/tests/README.md` Mock 配置章节）：

| 路径 | 内容 | 测试场景 |
|------|------|----------|
| `/tmp/test-proc/cpuinfo` | Loongson 处理器信息 | get_cpu_info |
| `/tmp/test-proc/meminfo` | MemTotal 16384000 kB | get_memory_info |
| `/tmp/test-proc/loadavg`（高负载） | 4.52 3.81 2.90 | 高负载告警 |
| `/tmp/test-proc/loadavg`（正常） | 0.45 0.32 0.28 | 正常运行 |
| `/tmp/test-log/syslog` | 僵尸进程日志 | 日志诊断 |

**MCP Mock 工具返回值**（见 `tool-server/tests/README.md`）：
- get_cpu_info → cpu_percent=85, cores=4
- get_disk_usage → disk_usage=92%, largest_dir=/tmp/logs
- get_memory_info → 16GB total, 14GB used
- get_process_info → pid=12345, mysqld, cpu=78%
- delete_temp_files → deleted 2.3GB
- restart_service → FAILED, permission denied

**依赖注入**（见 `tool-server/README.md`）：
- `proc_path`: /tmp/test-proc
- `sys_path`: /tmp/test-sys
- `log_path`: /tmp/test-log
- `sandbox_root`: /tmp/sandbox

## E2E Mock 数据

前端 mock E2E 不启动后端，通过 Playwright route 直接 mock：

- `POST /api/chat`：返回预定义 SSE 序列，覆盖 `session_init`、`tool_call`、`tool_result`、`tool_approval_required`、`assistant`、`done`、`error`
- `GET /api/sessions`：返回会话摘要列表
- `GET /api/sessions/{chat_id}`：返回会话详情
- `DELETE /api/sessions/{chat_id}`：模拟删除成功
- `POST /api/tool-requests/{request_id}/approval`：回显审批状态

Live E2E 使用 `docker-compose.test.yml` 启动完整服务栈，各服务 Mock 配置同上述集成测试环境。详见 `docs/e2e测试.md`。
