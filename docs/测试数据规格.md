# 测试数据规格

本文集中说明测试数据来源、Mock 方式和稳定性要求。测试数据应尽量小、可读、确定，避免依赖真实 LLM、真实宿主机状态或外部网络。

## web-server 测试数据

web-server 测试通过依赖注入替换外部服务：

| 依赖 | 测试替身 | 目的 |
|------|----------|------|
| LLM Adapter | Mock LLM 响应序列 | 保证 Agent 流程可重复 |
| SessionManager | 内存实现或测试 DB | 验证会话生命周期 |
| AuditLogger | 内存实现或测试 DB | 验证审计事件 |
| ToolExecutor | fake executor 或 FastMCP mock | 验证工具调用和安全审查 |

核心 LLM 序列：

| 场景 | 输入 | 预期输出 |
|------|------|----------|
| 只读诊断 | “查看 CPU” | 先 tool_call，再 tool_result，最后 assistant 分析 |
| 高风险审批 | “清理磁盘” → “确认” | 先只读诊断，再生成审批请求 |
| 审批拒绝 | 用户拒绝 ToolRequest | assistant 收到拒绝反馈并给出新提示 |
| 错误恢复 | LLM 返回 prompt_too_long 等错误 | 触发压缩、重试或表面错误 |

测试 rules.json 使用最小规则：

```json
{
  "whitelist": [{ "tool_name": "delete_temp_files" }],
  "blacklist": [{ "tool_name": "reboot_system" }]
}
```

## tool-server 测试数据

tool-server 单元测试使用临时目录和本机只读信息，不依赖生产宿主机路径。

| 数据 | 用途 |
|------|------|
| `tmp_path` sandbox | 验证 bash 执行、超时和 cwd 规则 |
| `ToolServerConfig` | 注入 sandbox、cache_ttl、host_exec 等配置 |
| `DummyEbpfRuntime` | MCP 集成测试中替代 eBPF daemon，避免依赖内核权限 |

MCP 集成测试使用 `fastmcp.Client(server)` 直接连接内存中的 FastMCP server。这样能覆盖 MCP 协议对象、工具发现、`call_tool`、结构化返回和 `execute_tool` 安全链路，同时避免端口冲突。

当前 MCP 集成覆盖：

- 工具列表包含 `get_cpu_info`、`bash`、`bash_classify`、`execute_tool`。
- `bash_classify("ls /tmp")` 返回 `{"safe": true}`。
- `bash_classify("rm -rf /tmp")` 返回 `{"safe": false}`。
- `execute_tool` 收到 `approval_status=PENDING` 时返回 `SECURITY_VIOLATION`。
- `execute_tool` 收到合法 APPROVED 请求时能执行 `bash` 并返回 `SUCCEEDED`。

## 前端 Mock E2E 数据

Mock E2E 数据定义在 `frontend/vue-project/tests/e2e/helpers.ts`。

SSE helper 输出当前前端真实消费的字段：

| 事件 | 关键字段 |
|------|----------|
| `assistant` | `delta` |
| `assistant_done` | message 完成信号 |
| `tool_call` | `call_id`、`tool_name`、`params`、`is_read_only` |
| `tool_result` | `call_id`、`execution_status`、`output` |
| `tool_approval_required` | `request_id`、`call_id`、`tool_name`、`params`、`reason` |
| `error` | `code`、`message` |
| `done` | 流结束 |

REST mock 覆盖：

- `GET /api/sessions`
- `GET /api/sessions/{chat_id}`
- `DELETE /api/sessions/{chat_id}`
- `POST /api/tool-requests/{request_id}/approval`

## Live E2E 数据

Live E2E 使用 `docker-compose.test.yml` 启动真实服务栈。数据写入测试 PostgreSQL 容器，不使用生产数据库。

注意：

- PostgreSQL 不映射宿主机 `5432`，避免和本机数据库冲突。
- web-server 使用 read-only 文件系统，`/tmp` 和 `/app/logs` 通过 tmpfs 提供。
- tool-server 暴露 `11451`，web-server 通过测试配置发现工具。
- Live E2E 不断言自然语言回复的固定内容，只断言链路可用和用户可见状态。

## 数据维护规则

- 测试数据字段必须和前端 `src/domain/sse-events.ts` 保持一致。
- Mock E2E 修改 SSE 字段时，必须同步 `helpers.ts` 和相关断言。
- Live E2E 不应依赖真实外部 LLM；测试栈应使用受控 mock 或测试配置。
- 测试数据只表达一个场景，不复用过大的“万能 fixture”。
