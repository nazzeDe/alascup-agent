# 开发环境

日常开发在本地使用 uv（Python）和 bun（前端）直接运行，不依赖 Docker。
所有构建、测试命令通过 `make` 统一入口（见项目根目录 `Makefile`）。

## 运行时依赖

- Python ≥ 3.11 + `uv`
- Bun（前端构建工具）
- Docker（仅用于交叉构建 LoongArch 镜像）

## 日常开发

各服务手动启动：
```bash
cd web-server && uv run uvicorn src.main:app --reload   # web-server dev
cd tool-server && uv run fastmcp run src/main.py        # tool-server dev
cd rag-server && uv run fastmcp run src/main.py         # rag-server dev
cd frontend && bun run dev                              # frontend dev
```

### 首次启动

1. 安装 Python 3.13+、uv、Bun 和 Docker
2. 在仓库根目录准备 `web-server/config/` 下的 `servers.json`、`llm.json`、`rules.json`、`prompt.md`（可选，需在启动时配置 prompt_path）
3. 先运行 `make test` 或对应子项目测试，确认环境可用，再启动开发服务
4. 如果只改某个服务，优先只启动该服务和它的直接依赖，减少干扰

### 常见问题

- rag-server 启动失败时，检查 `EMBEDDING_API_BASE` 环境变量是否已设，指向 LLM 提供方的 Embedding API
- web-server 访问失败时，先检查 `web-server/config/llm.json` 和 `servers.json`
- 前端无法连后端时，先确认 `web-server` 是否运行在 8000 端口
- 测试失败但本地服务正常时，优先检查测试环境与生产环境差异，尤其是 LLM mock、数据库模式和审批超时

## 交叉构建（LoongArch 镜像）

### 安装 LoongArch 运行时支持
安装 `qemu-user-static` 和 `binfmt` 支持包（包名因发行版而异，LoongArch 支持需内核 5.10+）。

### 配置 Docker 的多架构运行支持
```bash
docker run --privileged --rm ghcr.io/loong64/binfmt --install all
```

### 验证 LoongArch 容器运行
```bash
docker pull --platform linux/loong64 ghcr.io/loong64/kylin:11-default
docker run --rm -it --platform loong64 ghcr.io/loong64/kylin:11-default
```
容器内执行 `uname -m`，应返回 `loongarch64`。

## 测试环境差异

`docker-compose.test.yml` 与生产配置的关键差异：

| 配置项 | 生产 | 测试 |
|--------|------|------|
| tool-server volumes | `/proc:/host/proc:ro`, `/sys:/host/sys:ro`, `/var/log:/host/var/log:ro` | 无宿主机挂载，使用临时目录 |
| web-server LLM | 真实 API | MockLLMAdapter（预定义响应） |
| rag-server ChromaDB | 持久化卷 `rag-data` | 内存模式 |
| web-server 存储 | PostgreSQL（持久化） | PostgreSQL（临时容器，同生产 schema） |
| tool-server sandbox | 独立 path + capability | 临时目录 `tmpfs` 无额外 capability |
| rag-server embedding | 真实 Embedding API | 真实 Embedding API |
| 审批超时 | 300s | 3s（通过环境变量注入） |
| 日志 | 写入 `./logs/` | stdout（不持久化） |
