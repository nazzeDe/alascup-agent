# 麒麟远程调试启动流程

本文是 `alascup-agent` 在麒麟远程服务器上启动，并通过本机 Chrome DevTools 调试的标准流程。后续 agent 直接按本文执行，不重新设计启动方式。

## 固定环境

| 项目 | 值 |
|---|---|
| 本机项目目录 | `/home/nazze/Studio/myrepo/alascup-agent` |
| 远程主机 | `100.102.147.12` |
| 远程用户 | `vmuser` |
| 远程项目目录 | `/home/vmuser/alascup-agent` |
| 远程系统 | 麒麟 Linux Advanced Server V11 |
| 远程架构 | `loongarch64` |
| 前端容器内部端口 | `8080` |
| 前端远程宿主机端口 | `18080` |
| Web Server 远程宿主机端口 | `11450` |
| 本机浏览器地址 | `http://127.0.0.1:18080/` |

远程服务器的系统 Nginx 已占用 `80` 端口，因此应用前端使用 `18080`。不要为了本项目停止系统 Nginx。

远程服务器不使用 Docker Compose，也没有 Bun。必须在本机构建前端 `dist`，同步到远程后再构建镜像。

## 代码修改边界

本机仓库是代码的唯一修改源。涉及 Python、TypeScript/Vue、Shell、Dockerfile 或其他仓库代码时，严格执行：

```text
本机 apply_patch/编辑
  -> 本机检查和构建
  -> rsync 同步到远程
  -> 远程 build-images.sh 构建
  -> 远程 run-containers.sh 启动
```

不要在远程仓库中使用 `vi`、`sed -i`、重定向或脚本直接修改代码文件。远程只允许做以下运行时操作：

- 执行镜像构建和容器启动
- 检查日志、端口、容器和健康接口
- 修改远程环境专属配置，例如 `web-server/config/llm.json` 的格式问题
- 修改服务器级 SSH 转发配置，以建立本机调试隧道

任何远程代码变更都必须先回写成本机仓库中的正式修改，再重新同步；不能把远程临时修改当作代码源。同步后可用下面的命令核对关键文件：

```bash
sha256sum scripts/run-containers.sh web-server/Dockerfile tool-server/Dockerfile \
  frontend/vue-project/dist/index.html
```

## 凭据规则

文档不保存以下敏感信息：

- SSH 登录密码
- `~/Documents/gitkey` 中的 GitHub Fine-grained PAT
- `web-server/config/llm.json` 中的 LLM API Key
- `TOOLSERVER_SHARED_SECRET`

SSH 密码只从当前用户消息或安全凭据源读取，使用后不要写入文件、命令历史或日志。远程仓库已经是最新目录时，不要为了启动流程重复拉取 GitHub。

## 启动流程

### 1. 设置连接变量

在本机终端执行。`REMOTE_PASSWORD` 使用当前用户提供的密码，不要把真实值写进脚本或文档。

```bash
cd /home/nazze/Studio/myrepo/alascup-agent

export REMOTE_USER=vmuser
export REMOTE_HOST=100.102.147.12
export REMOTE_DIR=/home/vmuser/alascup-agent
export SSH_TARGET="$REMOTE_USER@$REMOTE_HOST"
export REMOTE_PASSWORD='<从当前用户会话取得，不要持久化>'
export SSHPASS="$REMOTE_PASSWORD"
```

如果本机没有 `sshpass`，改用交互式 `ssh`、`rsync`，不要把密码拼进命令行参数。

### 2. 本机构建前端

```bash
cd /home/nazze/Studio/myrepo/alascup-agent/frontend/vue-project
bun install --frozen-lockfile
bun run build

cd /home/nazze/Studio/myrepo/alascup-agent
bash scripts/tests/run-containers_test.sh
```

必须确认 `dist/index.html` 和 `dist/assets/` 已生成。`vue-tsc` 或 Vite 构建失败时，不要继续同步和部署。

### 3. 同步构建产物和部署文件

`dist` 使用 `--delete`，确保远程不会残留旧 hash 资源。只同步部署所需文件，不覆盖远程 `web-server/config/`，因为其中包含远程环境的 LLM 配置和密钥。

```bash
cd /home/nazze/Studio/myrepo/alascup-agent

sshpass -e rsync -az --delete \
  -e 'ssh -o StrictHostKeyChecking=accept-new' \
  frontend/vue-project/dist/ \
  "$SSH_TARGET:$REMOTE_DIR/frontend/vue-project/dist/"

sshpass -e rsync -az \
  -e 'ssh -o StrictHostKeyChecking=accept-new' \
  scripts/run-containers.sh \
  "$SSH_TARGET:$REMOTE_DIR/scripts/run-containers.sh"

sshpass -e rsync -az \
  -e 'ssh -o StrictHostKeyChecking=accept-new' \
  web-server/Dockerfile \
  "$SSH_TARGET:$REMOTE_DIR/web-server/Dockerfile"

sshpass -e rsync -az \
  -e 'ssh -o StrictHostKeyChecking=accept-new' \
  tool-server/Dockerfile \
  "$SSH_TARGET:$REMOTE_DIR/tool-server/Dockerfile"
```

不要把两个同名 `Dockerfile` 一起同步到项目根目录；它们必须分别放在 `web-server/` 和 `tool-server/`。

### 4. 远程构建并启动

建立一个交互式 SSH 会话：

```bash
ssh -tt "$SSH_TARGET"
cd ~/alascup-agent
sudo -v
sudo ./scripts/build-images.sh
sudo env FRONTEND_HOST_PORT=18080 TOOLSERVER_HOST_EXEC=chroot ./scripts/run-containers.sh
```

`build-images.sh` 会自动识别 `loongarch64`，构建：

- `alascup-frontend:latest`
- `alascup-web-server:latest`
- `alascup-tool-server:latest`

当前 Dockerfile 直接使用 `pip install .`，不在运行时镜像中安装不需要的 `uv`，避免 LoongArch 上触发长时间 Rust LTO 构建。

`run-containers.sh` 的当前行为：

- 原生 `docker run`，不依赖 Compose
- 自动设置 Tool Server 的 `TOOLSERVER_HOST=0.0.0.0`
- 麒麟/LoongArch 默认使用 `TOOLSERVER_HOST_EXEC=chroot`，避开容器内 `nsenter` 的 `nsfs` 兼容性问题
- 为 Tool Server 和 Web Server 注入同一个运行时共享密钥
- 为 Tool Server 挂载 `/app/sandbox` 和内核 BTF
- 每次运行都清理旧的四个应用容器，确保使用当前镜像重新创建
- 前端宿主机端口默认是 `18080`，不占用系统 Nginx 的 `80`
- 只有明确设置 `CLEAN_VOLUME=1` 才会删除数据库卷；开发调试默认不要设置它

### 5. 远程验证

仍在远程 SSH 会话中执行：

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
curl -sS http://127.0.0.1:11450/api/health
curl -sS http://127.0.0.1:18080/api/health
```

预期：

- `postgres`、`tool-server`、`web-server`、`alascup-frontend` 均为运行状态
- `/api/health` 返回 `"status":"ok"`
- `checks.postgres` 为 `ok`
- `checks.tools_discovered` 大于 0，当前环境通常为 `18`

如果 Web Server 重启，先检查而不是重建镜像：

```bash
sudo docker logs --tail 100 web-server
python3 -m json.tool web-server/config/llm.json >/dev/null
```

不要用本机配置覆盖远程 `llm.json`。若只是 JSON 格式错误，只修复格式，保留远程密钥和参数。

Tool Server 探活出现 warning 不一定表示失败；MCP `/mcp` 对裸 GET 可能不返回 2xx。以 Web Server 健康检查中的 `tools_discovered` 和实际 API 响应为准。

## 建立本机 SSH 隧道

先退出或保留远程 shell 均可，另开一个本机终端执行：

```bash
ssh -N -T \
  -o ExitOnForwardFailure=yes \
  -L 18080:127.0.0.1:18080 \
  -L 11450:127.0.0.1:11450 \
  "$SSH_TARGET"
```

保持这个进程运行。另开本机终端验证：

```bash
curl -sS http://127.0.0.1:18080/api/health
```

如果看到 `administratively prohibited`，远程 SSH 服务禁止 TCP 转发。使用 sudo 修复并 reload：

```bash
sudo sed -i 's/^[[:space:]]*AllowTcpForwarding[[:space:]].*/AllowTcpForwarding yes/' /etc/ssh/sshd_config
sudo sshd -t
sudo systemctl reload sshd
```

然后终止旧隧道，重新执行隧道命令。不要把 `GatewayPorts` 改成 `yes`；本流程只需要本机回环地址转发。

## Chrome DevTools 验证

使用 Chrome DevTools MCP：

1. 新建页面并打开 `http://127.0.0.1:18080/`。
2. 使用页面 snapshot 确认出现 `Alascup Agent`、`New Session` 和消息输入框。
3. 查看 Network，确认 `/`、主 JS/CSS、`/api/sessions` 都返回 200。
4. 查看 Console，确认没有运行时错误。
5. 需要测试真实对话时，再发送测试消息；不要在未获用户确认时触发可能执行工具的操作。

浏览器入口只使用 `18080`。后端 `11450` 仅用于直接 API 调试。

## 常见问题

| 现象 | 处理 |
|---|---|
| `docker` permission denied | 所有远程 Docker 命令加 `sudo`；`vmuser` 默认不在 `docker` 组 |
| 远程 `80` 已被占用 | 脚本默认使用 `18080`；不要停止系统 Nginx |
| `AllowTcpForwarding` 被拒绝 | 按上面的 sshd 配置修复、`sshd -t`、reload、重建隧道 |
| Web Server `JSONDecodeError` | 检查远程 `web-server/config/llm.json` 的 JSON 格式，不覆盖远程凭据 |
| Tool Server 探活 warning | 直接验证 `/api/health` 的 `tools_discovered`，不要仅依据脚本 warning |
| 页面 200 但旧 JS 资源 | 重新本机构建并用 `rsync --delete` 同步 `dist`，再重建前端镜像 |
| 数据库数据需要保留 | 不设置 `CLEAN_VOLUME=1`；脚本每次重建容器但默认保留 `pgdata` |

## 停止调试

本机隧道终端按 `Ctrl-C`。容器默认是 `unless-stopped`，不需要每次调试结束都删除；需要停止服务时在远程执行：

```bash
cd ~/alascup-agent
sudo docker stop alascup-frontend web-server tool-server postgres
```

不要使用 `docker volume prune` 或删除 `pgdata`，除非用户明确要求清空测试数据。
